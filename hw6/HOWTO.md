# VRP Local Runner

В репозитории добавлены:

- `checker.py` — полный чекер решения VRP.
- `run.sh` — компиляция `main.cpp` и прогон всех тестов из `config.json`.

## Формат входа

Каждый файл в `data/` имеет формат:

```text
n vehicles capacity
demand_1 x_1 y_1
demand_2 x_2 y_2
...
demand_n x_n y_n
```

Принято, что вершина `1` — депо. У неё обычно `demand = 0`.

## Формат вывода солвера

Формат, который ожидает чекер:

```text
<total_cost>
<k1> <v11> <v12> ... <v1k1>
<k2> <v21> <v22> ... <v2k2>
...
```

Где:

- первая строка — суммарная длина всех маршрутов;
- каждая следующая строка — один маршрут;
- `ki` — число вершин в маршруте;
- вершины в маршрутах задаются в `1`-индексации;
- депо `1` внутри маршрутов указывать не нужно и нельзя.

Пример:

```text
387.123456
4 2 5 7 3
3 4 6 8
0
```

Это значит:

- первый маршрут: `1 -> 2 -> 5 -> 7 -> 3 -> 1`
- второй маршрут: `1 -> 4 -> 6 -> 8 -> 1`
- третий маршрут пустой

Число строк маршрутов может быть меньше либо равно числу машин из теста.

## Что проверяет чекер

`checker.py` проверяет:

- корректность формата вывода;
- что все индексы вершин целые и лежат в допустимом диапазоне;
- что депо `1` не встречается внутри маршрутов;
- что каждый клиент `2..n` посещён ровно один раз;
- что число маршрутов не превышает число доступных машин;
- что суммарный demand на каждом маршруте не превышает capacity;
- что заявленная в первой строке стоимость совпадает с реально пересчитанной по евклидовым расстояниям.

Если хоть одно из этих условий нарушено, решение считается невалидным.

## Как запускать

Прогон всех тестов из `config.json`:

```bash
./run.sh
```

Если нужно собрать не `main.cpp`, а другой файл:

```bash
./run.sh path/to/solver.cpp
```

По умолчанию на каждый тест даётся `120` секунд. Можно поменять:

```bash
TIME_LIMIT=30 ./run.sh
```

## Что выводит `run.sh`

Скрипт печатает таблицу по всем тестам из `config.json`:

- `Status`:
  - `OK` — решение валидно;
  - `WA` — вывод есть, но он некорректен;
  - `RE...` — программа завершилась с ненулевым кодом;
  - `ERR` — проблема со входом, конфигом или запуском.
- `Claimed` — число из первой строки вывода солвера.
- `Actual` — стоимость, которую пересчитал чекер.
- `Score` — лучший набранный балл за этот тест.
- `Next` — ближайший ещё не пройденный порог.
- `Note` — первая найденная проблема или краткая пометка.

В конце печатается суммарный балл.

## Отдельная проверка одного вывода

Если нужно проверить один конкретный файл с ответом:

```bash
python3 checker.py --instance data/vrp_16_3_1 --output answer.txt
```

Это удобно, если вы сами хотите запускать бинарник отдельно и потом локально проверять только один инстанс.
